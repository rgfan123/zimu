# 01 — 按业务对象重组导航，并收纳京东工具

**What to build:** 运营人员从导航中直接找到订单、履约和系统管理等业务对象；低频的京东连接、基础资料与原始查询统一收纳到“系统管理 → 京东工具”，不再挤占作业中心；库存中心仍由后续真实总库存能力负责交付。

**Blocked by:** None — can start immediately

**Status:** resolved

**Claimed by:** codex-root

- [x] 作业中心仅保留人工复核、渠道消息、履约任务、采购协同、文件作业和发货记录等高频运营入口。
- [x] 京东连接检查、京东基础资料、库存/序列号/专业供应链单据/退货退供原始查询收纳到“系统管理 → 京东工具”的清晰层级下，不把这些专业单据命名为公司总订单。
- [x] 公用的履约方配置在“系统管理”中有中性、可发现且可编辑的入口，不只藏在“京东工具”中，也不把第三方履约方误命名为京东能力。
- [x] 订单中心仍以“全部订单”作为唯一总订单入口，不新增“京东订单”一级业务板块。
- [x] 保留现有京东页面的 URL 可访问性，旧书签和已分享链接不失效；`hideInMenu` 隐藏页仍不出现在菜单、但可由已注册路由直达。
- [x] 库存中心在真实总库存能力完成前不出现空壳一级入口，导航不宣称尚未提供的聚合能力。
- [x] 通过公开路由/菜单配置测试证明新分组、旧 URL 兼容、多层菜单展开和隐藏页可见性。

## Answer

已用一份不依赖 React 的生产导航元数据统一驱动路由绑定、菜单展开、顶栏归属和隐藏页可见性。作业中心收敛为六个高频入口；六个现有京东 URL 归入“系统管理 → 京东工具”；通用履约方配置已抽到独立可编辑页。全部订单仍是唯一总订单入口，未提前建立库存中心空壳。

本地验证：导航聚焦用例 8/8，前端全量 Node 用例 70/70，TypeScript 检查通过，`git diff --check` 通过；Standards 与 Spec 修复后独立复审均无 P0–P2。遵循用户关闭 Playwright/Chrome 的要求，本轮没有重启浏览器；实际 Ant Design 三级菜单的视觉证据未重拍。未 stage、commit、部署或上线。
