# 商品主数据补全与企微接收验收

**Status:** approved

## Problem Statement

系统当前只有少量演示 SKU，仓库中的京东商品编码工作簿尚未形成可重复、可审计的主数据导入；SKU 也缺少进货价和零售价。企微回调已有本地协议实现，但仍需证明真实配置下能接收用户消息，且不能把固定样本测试冒充真实平台验收。

## Decisions

- `京东商品编号.xlsx` Sheet1 的 JD 编码列是本轮 JD 商品范围的权威清单；空行忽略，重复 JD 编码必须显式报告和确定性归并，不按商品名模糊合并。
- `合作商品价格查询导出_按商品名称去重.xlsx` 的“一件代发价格”映射为 SKU 进货价，“建议售价”映射为 SKU 零售价；只有精确商品名匹配才自动导入，未覆盖商品保持未定价并进入导入报告。
- 两个价格是可为空、非负、两位小数的人民币金额事实；API 使用 decimal string，UI 明确显示“未定价”，不以 0 代表未知。
- 导入必须可重复执行：同一源文件重放不重复创建 Product、SKU、ProviderSku 或价格；内容漂移必须可见。
- 企微“正常接收”分两层证明：普通自动化证明签名、解密、白名单、幂等持久化和固定回执；真实可用必须由当前部署域名、真实凭据、业务群和真实用户消息完成验收。缺少外部条件时如实记录门禁。

## Testing Decisions

- 商品导入以公开导入命令/API + 真实 PostgreSQL 为主 seam，断言清单行数、唯一 JD 编码、价格覆盖/缺失报告和幂等重放。
- 价格以 SKU CRUD 公共 API + 前端主数据页面为 seam，断言 decimal string、未知为 null、版本冲突与金额校验。
- 企微以公开加密 callback HTTP + 真实 PostgreSQL 为自动化 seam；真实群消息另做受控验收，不运行未经授权的外部写操作。
