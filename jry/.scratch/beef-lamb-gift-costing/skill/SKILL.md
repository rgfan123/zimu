# 京东云仓·礼包额外费用计算

## Overview

组礼包时，货值之外还要付给京东一笔钱：运费、出库操作费、耗材、入库验收费、仓库资源调节费，
以及可选的存储费。这笔钱**单均约 30~50 元**，同一个礼包发北京和发福州能差 16 元——
不算清楚，礼包毛利就是假的。

**核心原则：这些费率不能凭印象估，必须用脚本算。** 全部费率反推自真实结算账单并逐单验证过
（运费 735/738、出库费 753/753、耗材 2139/2139 精确命中），手工估算做不到这个精度，
而且有几个反直觉的坑（见 Common Mistakes）。

## When to Use

**必须使用**（不要手工估）：
- 给礼包定价、算礼包毛利、评估某个礼包组合划不划算
- 比较同一礼包发往不同地区的成本差异
- 核对京东账单、复盘实际支出
- 回答任何形式的「这个礼包发到 X 要多少钱」

**不适用，别用本 skill 的数字**——需同时满足「货在京东云仓」+「用途是组礼包」：

| 不适用 | 为什么 |
|---|---|
| 第三方仓 / 自有仓发货 | 费率是京东云仓合同价，别家不同 |
| 一件代发经销品 | 承运方是顺丰/德邦，运费体系完全不同 |
| 送仓经销品 | 不走 B2C 冷链快递 |
| 京东其他仓发货 | 账单只覆盖石家庄冷链C仓这一个仓 |
| 常温、非冷链商品 | 费率表是「B2C冷链仓储」专项价 |
| 大宗/整车/自提 | 装卸费口径不同，样本仅 6 行 |

判断依据：看 SKU 主数据的履约方是不是京东。是经销品目录（送仓/一件代发）来的，**停下，本 skill 不适用**。

**不算**：商品进货价、加工成本、包装设计费、平台扣点、账期成本。那些不在本 skill 范围。

## 成本看哪列、售价看哪列

本 skill 只算**从京东仓发出去**的额外费用。要算礼包毛利，还需要货值成本和售价。

### 优先从数据库取（已落库，不用翻 Excel）

| 要什么 | 取哪里 | 对应成本表列 |
|---|---|---|
| **礼包货值成本** | **`app.skus.purchase_price`** | AI 列「线下供货成本/份」 |
| **对外售价** | **`app.skus.retail_price`** | AJ 列「售价」 |
| 40 个成本构成明细 | `app.product_archive_sheets.fields`（JSONB 数组 `{name,value}`） | 成本表全部列 |

MCP 工具 `search_skus` 直接返回这两个价格字段，`estimate_bundle_economics` 可做礼包测算。

> 注：`product_archive_sheets` 是 2026-08-27 的**一次性冻结快照**，之后新建的 SKU 不在里面，
> 且其「经营状态」列不可信（标"停产"的 42 行里有 23 行实际在售）。判断在售看 `skus.active`，不要看档案。

### 成本表列号对照（需要看构成时）

`A产品成本核算26.3.29.xlsx` 的 `成品` sheet：

| 列 | 含义 | 用途 |
|---|---|---|
| W | 加工后成本/份 | 只到加工，**不是礼包成本口径** |
| AD | 耗材/份 | 商品自己的内包装（盒/袋/膜/签） |
| AG / AH | 物流（原料进货 / 成品送货）/kg | 入仓之前的物流 |
| **AI** | **线下供货成本/份** | **= W + AD + 物流，礼包货值成本用它** |
| **AJ** | **售价** | 对外零售价 |
| AR | 供货价 | 给渠道的价 |
| AL/AM · AN/AO | 账期比例·费用 / 扣点·费用 | 随客户渠道变，非商品固有 |

### 为什么用 AI 而不是 W —— 两段成本不重叠

看列名容易误以为 AI 里的「耗材」「物流」会和本 skill 算的重复，**实际不重叠**：

| AI 里的项 | 是什么 | 和本 skill 撞不撞 |
|---|---|---|
| AD 耗材/份（样例 0.24 元） | 商品自己的内包装，全部来自 X 列「盒/袋」 | 不撞。礼包里每块肉照样单独包着 |
| **AB 泡沫箱/纸箱+冰袋** | 真正会撞车的外包装 | **该列值为 0，压根没计** |
| AG/AH 物流（样例各 1.00 元/kg） | 原料运到工厂、成品送到仓库 | 不撞。都在**入仓之前** |

本 skill 算的是**出仓之后**：京东的泡沫箱冰袋、出库操作、发到消费者的快递费。
`AI（到仓成本）` + `本 skill（出仓成本）` 严丝合缝，无重复、无遗漏。

```
礼包落地成本 = Σ(组件 AI × 数量)  +  本 skill 算出的额外费用
礼包毛利     = 客户采购价 − 礼包落地成本
```

样例八件套：AI 合计 **213.00** 元 + 额外费用（发北京 33.46 / 发福州 49.46）。

### 三个价别混

| 名称 | 谁付给谁 | 举例 |
|---|---|---|
| **客户采购价** | 客户付给我们 = **我们的收入** | 300 元 |
| **对外售价** | 消费者付给客户 = 客户的收入，**不进我们的毛利** | 400 元 |
| **落地成本** | 我们付出去的 = 货值(AI) + 额外费用 | 本 skill 算后半截 |

算毛利用**客户采购价减落地成本**。那 400 元是客户的加价空间，跟我们的毛利无关。

## 立刻可用

```bash
S=~/.claude/skills/jd-fee-calc/scripts

# 按礼包组成算（推荐，自动查商品体积重量、自动选箱）
python3 $S/jdfee.py --dest 北京朝阳区 --bundle "牛腩块×1,羊排块×1,羊蝎子×1" --ice-frozen 4

# 手工给重量（不知道箱子多大时，别给 --volume，让它按历史档案估）
python3 $S/jdfee.py --dest 福州市 --weight 3.8 --goods-volume 17500 --items 8 --sku-count 8

# 已知京东实际用了多大的箱子（复盘对账时）
python3 $S/jdfee.py --dest 福州市 --weight 3.8 --volume 32630 --items 8 --sku-count 8

# 查有哪些商品 / 目的地
python3 $S/jdfee.py --list-goods 羊
python3 $S/jdfee.py --list-dest 江苏

# 给其他程序用
python3 $S/jdfee.py --dest 上海浦东新区 --bundle "羊小腿×2" --json
```

## 计算模型

```
额外费用 = 运费 + 出库操作费 + 耗材 + 入库验收费 + 仓库资源调节费 [+ 存储费]
```

**1. 计费重量**（运费的输入，不是实际称重）
```
计费重量 = max( 进位(实重), 进位(包裹体积cm³ ÷ 8000) )
进位 = 向上取整到 0.5kg，但超出整数倍 ≤0.005kg 不进位（秤容差）
```
注意是**包裹体积**（京东装的那个泡沫箱），不是货物净体积。冷链礼包几乎总是体积重 > 实重，
所以**运费由箱子大小主导，不是由肉的净重主导**。

**装箱由京东决定，不是商家可选项** —— 所以脚本不做「选最小够用的箱」这类推算，
而是按货物体积查历史实际用箱。

**2. 运费**（按目的城市分档，不是按省）
```
运费 = 四舍五入(常数 + 斜率 × 计费重量) × (1 − 促销折扣率)
```
| 档位 | 覆盖 |
|---|---|
| 12 + 2×重量 | 北京 |
| 11 + 2×重量 | 天津、河北北部 |
| 10 + 2×重量 | 河北近京 |
| 10 + 5×重量 | 山东、山西、河南、内蒙古、辽宁、江苏北、安徽、湖北、陕西 |
| 10 + 6×重量 | 上海、浙江、福建、广东、川渝、湘赣、甘青、黑吉、江苏南 |
| 10 + 8×重量 | 新疆 |

**3. 出库操作费**（订单生产服务，三种规则）
| 情形 | 费用 |
|---|---|
| 原包发货、仅贴单 | 0.6 元/件 |
| 拆包·多SKU（**礼包属此类**） | 1.6 元/单 + 超3件部分 0.2 元/件 |
| 拆包·单SKU | 1.2 元/单 + 超3件部分 0.1 元/件 |

**4. 耗材**（泡沫箱+保温袋+冷媒）——按**货物体积**查历史均值，不按件数：

| 货物体积 cm³ | 耗材均值 | 中位 | 档内标准差 | 典型箱 | 样本 |
|---|---|---|---|---|---|
| <3000 | 4.97 | 2.90 | ±3.00 | 4号 (54%) | 71单 |
| 3000–6000 | 5.68 | 3.40 | ±3.34 | 4号 (63%) | 299单 |
| 6000–11000 | 5.51 | 2.90 | ±3.56 | 4号 (52%) | 137单 |
| 11000–18000 | 9.42 | 9.40 | ±3.80 | 6号 (60%) | 81单 |
| >18000 | 11.33 | 9.40 | ±4.54 | 6号 (96%) | 165单 |

区间为**左闭右开**：体积正好 3000 落「3000–6000」档，正好 18000 落「>18000」档。

为什么按体积不按件数：体积对耗材成本的解释力更强（R² 0.379 vs 0.340），
而且体积分档单调递增，件数分档在 3–4 件处反而倒挂（4.62 < 1–2件的 5.97）。

**这一项是估算，不是精确值** —— 档内标准差 3~4.5 元，是全部费用里最不确定的一块。
单价本身（泡沫箱 0.9~5.5、保温袋 0.5~1.1、冷冻冰袋 0.3、干冰 0.9）是精确的，
不确定的是京东会用哪个箱、放几个冰袋。

**5. 其余**：入库验收 0.03 元/件；仓库资源调节费 0.2 元/票；存储费 4 元/方/天（默认不计）。

## 关键参数怎么调

| 参数 | 默认 | 什么时候要改 |
|---|---|---|
| `--freight-discount` | 0（合同价） | 京东按月给促销折扣，历史值 5月0.30 / 6月0.40 / 7月0.20，**未来月份未知**。报价留余量就用 0；复盘实际支出才填当月实际折扣。**新疆不参与折扣。** |
| `--storage-days` | 0（不计） | 存储费按月对账，是否摊进单件成本是业务口径问题。三个月存储费 6744 元、单均 8.96 元，**不小**，做完整成本时应考虑。 |
| `--original-pack` | 关 | 原包直发、只贴面单时打开，出库费从 1.6+0.2 变 0.6/件。礼包重新装盒**不适用**。 |
| `--box` / `--bag` | 按货物体积查历史典型箱 | **只在已知京东实际用了哪个箱时才手工指定**（比如复盘对账）。预估场景别乱指定——箱子不是你选的。 |
| `--no-packing` | 关 | 完全不用历史档案（耗材记 0），自己用 `--box`/`--ice-*` 逐项指定时用。 |
| `--sku-count` | 由 bundle 推断 | 手工给重量时必须给，否则单品/多品判错，出库费差 0.4~0.1/件。 |

**两个体积参数别搞混**（这是最容易算错的地方）：

| 参数 | 含义 | 用在哪 |
|---|---|---|
| `--goods-volume` | **货物**净体积 | 查耗材档位。`--bundle` 会自动算 |
| `--volume` | **包裹**体积（京东那个泡沫箱） | 算抛重和存储费。**给了就直接用，不会被历史档案覆盖** |

预估场景：只给 `--goods-volume`（或用 `--bundle`），包裹体积交给历史档案推。
复盘对账：已知实际箱号时给 `--volume`，拿到的才是真实数。

## 使用提示（给 agent）

- **先查再算**。商品名不确定先 `--list-goods`，目的地不确定先 `--list-dest`。脚本找不到会报错并给候选，不会瞎猜。
- **非法输入一律报错，不会静默算出一个看着正常的错价**：件数<1、重量≤0、折扣不在 [0,1)、箱号袋号越界、bundle 数量非正整数，都会拒绝执行并说明原因。看到 `✗` 就是输入有问题，别忽略。
- **省名 vs 城市名**：传城市名最准。只传省名会用「该省多数城市的档位」估算，输出会标 `[省级估算]`。**同省不同市可能不同档**（江苏南京 5 元档、无锡 6 元档），跨档省份脚本会额外警告。
- **注意输出里的提示行**：`⚠` 是可能算错的地方，`·` 是口径说明。
- **耗材那一项是估算**。输出会标出所在体积档、历史均值、中位数和标准差。做定价时如果这单利润薄，
  注意耗材可能比均值高 3~4 元。要保守就手工按最贵情形算（6号箱 5.5 + 6号袋 1.1 + 干冰若干）。
- **超过 15kg 会告警**。公式只在 ≤15kg 验证过；账单里 >40kg 的实付比公式高约 12%，别拿超重结果直接报价。
- **牛腱子档案可疑**（账单记 40cm³/1kg，物理上不可能），脚本会标 `⚠档案可疑`，遇到时改用 `--volume` 手工给。
- 要把结果喂给别的程序用 `--json`。

## Common Mistakes

这几条都是开发这个 skill 时真实踩过的坑，不是假想。

**1. 把「标价」当「合同价」** —— 账单里 `原始金额` 是标价，`结算金额` 才是实际付的合同价，
两者差很大（入库验收标价 0.2，合同价 0.03，差 6.7 倍）。曾据此误判「京东价格表写错了」，
实际价格表完全正确。**看账单核对时永远看结算金额。**

**2. 以为运费按净重算** —— 冷链礼包几乎总是体积重 > 实重，运费由**箱子大小**主导。
3.8kg 的礼包按 4.5kg 计费很正常。只给 `--weight` 不给体积信息会低估。

**3. 以为能选小箱省钱** —— 装箱由京东决定，不是商家可选项。别把「换小箱」写进优化建议。

**4. 混淆两个体积参数** —— `--goods-volume` 是货物净体积（查耗材档用），
`--volume` 是包裹体积（算抛重用）。给错会静默算出偏差 60% 的价格。用 `--bundle` 最安全，它自动处理。

**5. 把耗材估算值当精确值** —— 耗材是全部费用里唯一不精确的一项，档内标准差 3~4.5 元。
其他项都是精确公式，只有这项是历史均值。利润薄的礼包要留出这个余量。

**6. 忘了运费折扣是月度促销、不是合同价** —— 默认 `--freight-discount 0` 算的是合同价（不打折）。
历史上 5月30%/6月40%/7月20%，但**未来月份未知**。对外报价用 0 留余量；复盘实际支出才填当月实际值。
新疆不参与折扣。

**7. 凭列名断定重复计算** —— AI 列里有「耗材」「物流」，看着像会和本 skill 撞车，
**实际不撞**：那个耗材是商品自己的内包装（X列盒/袋），真正会撞的 AB 列「泡沫箱+冰袋」值为 0；
那个物流是入仓之前的。曾据此误判「礼包该用 W 列」，会把货值低估 9.57 元（213→203）。
**礼包货值成本用 AI 列 / `skus.purchase_price`。**

**7b. 把 AJ 当成本** —— AJ 是**售价**不是成本，误用会把成本高估 35%（样例 213 vs 273）。

**8. 用对外售价算毛利** —— 毛利 = **客户采购价** − 落地成本。
样例里 400 元是消费者付给客户的，不是付给我们的；我们的收入是 300 元那个数。

**9. 传省名当城市名** —— 档位按目的**城市**定，同省不同市可能差一档
（江苏南京 5 元档、无锡 6 元档）。传省名只能得到省内多数城市的估算，输出会标 `[省级估算]`。

## 数据来源与可信度

费率反推自京诚乾元（北京）供应链管理有限公司 **2026-05~07 三个月、四个科目、12 份京东物流结算账单**（收派服务费 / 仓储服务费-通用 / 仓储服务费-冷链 / 装卸服务费）。

全部取账单的 **`结算金额`（合同价）**，不是 `原始金额`（标价）—— 两者差很多，入库验收标价 0.2 而合同价 0.03。

| 项目 | 校验 |
|---|---|
| 运费公式 | 735/738 单精确命中（仅 3 单 >40kg 偏离） |
| 出库操作费 | 753/753 单 |
| 耗材单价 | 2139/2139 行 |
| 存储费 | 4416/4416 行 |
| 入库验收费 | 36/36 行 |

**局限**：
- **仓别单一**：全部数据来自石家庄冷链C仓一个仓。京东其他仓的合同价可能不同，不要套用。
- 只覆盖账单里实际发过货的 135 个城市；没发过的城市按省估算或无法计算。海南、西藏、港澳台无数据。
- 单一发货仓（石家庄冷链C仓）、非旺季。**旺季附加费、偏远地区附加费未在样本中出现**，不代表不存在。
- 这是**执行结果**不是合同条款。用于内部核算可靠；对外报价前建议与京东商务核对。
- 用户手上另有一张「5 分区运费表」（首重+分段续重的阶梯算法），与账单实际执行**结构性不符**（账单无阶梯，是线性），已确认不适用，勿采信。
