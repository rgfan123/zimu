# 09 — 客户区域画像与运费推断输出

**Type:** grilling
**Status:** open
**Blocked by:** 05、06

## Question

决策 8 定了「传了省份就用，没传按客户历史订单推断并显式标注为推断值」。本票定推断的算法与输出形态。

用户的原始动机很具体：「各个平台历史发的这些地区其实都留存在数据库里。比如彩食鲜总部在福建，就好多都是福建的订单。给他们核算运费的时候，这块儿就很重要了——他发哪儿，这个区域的运费不一样。」

同一个 3.8kg 礼包，1 区约 8~11 元，5 区（新疆海南）约 34 元，**25 元差价直接吃掉毛利**。

### 待决策点

1. **画像口径**：按客户（`customer_id`）聚合，还是按来源渠道（`source_channel`）？彩食鲜是渠道也是客户，两者在数据里可能不重合。
2. **统计窗口**：全部历史、近 12 个月、还是近 N 单？季节性（中秋/春节礼包）会不会让窗口选择产生偏差？
3. **权重**：按订单数还是按发货件数/重量加权？运费按重量计，用重量加权更贴近真实成本。
4. **输出形态**（决策 8 已定方向，本票定细节）：返回**省份分布 + 加权平均运费 + 最贵省份 + 最便宜省份**。是否还要返回：分区维度的聚合（比 34 个省更好读）、覆盖率（这个客户有多少订单未解析省份）、样本量（只有 3 单的客户，推断可信度很低）。
5. **可信度门槛**：样本量太少或未解析率太高时——照常返回但标低可信度，还是拒绝推断要求调用方传省份？倾向前者 + 明确标注，但门槛值要定。
6. **新客户**：没有历史订单的客户怎么办？（回退到全局分布 vs 拒绝推断）
7. **与票 05 的耦合**：本票的可信度直接取决于票 05 的回填命中率。命中率低于多少就该认为区域推断整体不可用？

### 与其他票的关系

- 依赖票 05（省份回填与命中率）、票 06（费率查询）。
- **不含商品偏好**：用户 2026-08-25 澄清「偏好」指销售偏好（自家主推策略，见票 13），不是客户历史偏好。客户历史商品偏好留在 map 雾区。
- 票 10 的工具出参需要携带本票定义的可信度标记——**推断值和确定值在出参里必须可区分**，否则调用方会把估算当事实。
