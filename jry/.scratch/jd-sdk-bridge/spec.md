# JD SDK 全接口接入

把京东物流 ISC SDK（`IntegratedSupplyChain_ISC_JAVA_6.1`）中尚未接入的接口按域接入系统：只读接口全部开放为受审计、脱敏的管理查询；写接口接入 seam 但默认锁死，仅显式启用后放行。用户疑问「为什么不直接用」的答案即本 spec 的约束来源。

## 现状

- SDK 共 **57 个接口**：已接入 8 个（6 读 + 2 写），未接入 49 个（30 读 + 19 写）。
- 已接入且生产验证通过的读接口：事业部发现、仓库查询（其余读接口已封装未验证）。
- 外部 gate 仍未解除：大部分接口在京东开放平台的授权状态未知；`queryOrderNosByPage` 等列表接口的权限需在开放平台后台确认。
- 生产凭据（`JD_LOP_*`）在 git-ignored 的本地 env 文件，探针只读、不打印密钥。

## 为什么不直接全接

1. **写接口风险**：约 21 个写接口，直接暴露会误触生产数据；项目原则是只读优先、写操作审计收口。
2. **接入成本**：每个接口要过防腐层（SDK DTO 不泄漏）、请求字段映射（曾踩 camelCase 坑）、响应归一化、PII 脱敏、审计、Mock、契约测试。
3. **权限未验证**：京东按接口授权，未验证的接口可能返回 `2001 / 没有事业部操作权限`。
4. **部分接口业务用不到**（序列号、加工单、销毁单、效期等），全接是永久维护负债。

## 约束

- 只读优先：写接口默认拒绝，显式启用 + 明确授权才放行；前端无一键写入口。
- 审计与脱敏：所有外部调用记审计；HTTP 边界剔除负责人、电话、邮箱、地址。
- Mock 隔离：默认 Mock 模式不触网；真实调用仅通过显式探针与 REAL 模式。
- 外部 gate：京东开放平台接口权限开通后才能做真实验证，不把 Mock 冒充真实权限。
- 领域词汇遵循 `CONTEXT.md`：订单/履约/履约方/出库单等术语不混用。

## 二阶段：京东云仓履约闭环（接入业务流程）

本节原有的 `issues/fulfillment-loop/00–05` 拆分已经封存，不再作为可领取工作。它把京东出库单错误地归属到逐行 Fulfillment，并包含未经确认的单位换算、地址猜测、缺货采购和真实写探针规则。

当前唯一权威的二阶段规范与实现票位于 `jd-fulfillment-loop` feature：从“统一 Shipment 级京东出库单边界”开始，按其阻塞边逐票推进。本 spec 继续只负责 JD SDK 接口覆盖，不再声明业务履约闭环的实现 frontier。
