# 工作台与数据中台页面形态原型

## Question

工作台 + 数据中台四页（履约总览 / 渠道分析 / 商品分析 / 履约分析）应该长什么样？

地图 Notes 已定「数据呈现设计」——口径、粒度、每页要哪些图都定了；**没定的是形态**：信息层级（分页 vs 单屏）、图表 vs 表格的主次、密度、下钻方式。这一层在 B4/B5 开工时靠想象选会浪费一天，故先原型。

## 形态（三个变体，结构性不同，非配色差异）

- **A 分页控制台**：AntD Pro 直觉版。完整 §22 侧边栏树，每页独立日期选择器；每页 = KPI 卡片行 + 图表卡网格 + 明细表。信息稀疏、翻页多、实现最省事。
- **B 单屏指挥中心**：四页合并为两个 bento 单屏，顶部**全局筛选条**（日期 + 渠道多选 + 双口径开关）驱动全部卡片联动；点柱/点扇区/点矩阵单元格 → 右侧抽屉下钻。侧边栏收成图标条换密度。
- **C 运营台账**：表格优先。KPI 退化为顶部一行紧凑数字条（带 sparkline），主体是可切维度（渠道/商品/品类/履约状态）的枢轴表，**双口径并排出列而非切换**，行内 mini bar；图表退到右侧窄栏。为每天盯数的运营设计。

## 数据

确定性假数据（固定随机种子）：近 30 天 × 四渠道，状态覆盖缺货 / 采购待处理 / 异常 / 回传失败。三个变体共用同一份数据，保证可比。

**商品目录用真实数据**（2026-08-11 用户提供 `京东商品编号.xlsx`，子牧牛羊肉）：12 个商品取自真实目录，带真实 EMG 京东编码、真实渠道商品名与包装数量。假名字（"黄心土豆"）会让密度判断失真——真实名长这样：`【京东配送】子牧原切纯肉羊腿肉500g*2袋`。

### 该表暴露的两个结构问题（超出本票范围，需回到 schema / 状态机票）

1. **同一京东 SKU 在不同渠道的包装数量不同**——羊棒骨 `EMG4418819505546` 在彩食鲜是 `500g*2`（数量 2）、在聚福宝是 `500g*3`（数量 3）；肩胛烤肉片 `EMG4418904463768` 是 4 vs 6。即渠道映射不是「名称→编码」的纯映射，还带**换算数量**。`db-schema-design` Q1 定的 `channel_skus`（internal_sku_id + 渠道编码）没有这一列，`aliases` 也没有。影响实发量口径：同样「1 件」在两个渠道对应的实际重量不同，PRD §21 的「实际商品数量」口径要先定清楚是渠道件数还是京东件数。
2. **礼包是组合品（BOM），当前 schema 无处安放**——`京东商品编号.xlsx` Sheet2 有约 25 个礼包（牛羊礼包5800g / 牛羊肉超级豪华大礼包10000g / 中秋礼包1 …），每个由 6~12 个 EMG × 数量组成。一行礼包订单在履约时要炸开成多个京东出库行。Q1 表清单（19 表）没有组合品/BOM 表，`CONTEXT.md` 也没有「组合品」这个词。影响：商品域 schema、履约拆分逻辑（一个 OrderLine → N 个 Fulfillment 行）、库存校验（礼包可用量 = 各成分可用量的木桶短板）、以及数据中台「商品分析」要按礼包统计还是按成分统计。

原型里对这两点只做了呈现层面的暴露（矩阵行上的「组合品 / 包装不一致」标记、下钻抽屉里的映射面板），**没有替 schema 票做决定**。

## 三个变体各自替我们试的问题

| | A 分页控制台 | B 单屏指挥中心 | C 运营台账 |
|---|---|---|---|
| 导航 | 完整 §22 树，五个页面 | 图标条，两屏 | 树，两页 |
| 筛选 | 每页各自的日期选择器 | 顶部**全局**筛选条驱动全部卡片 | 顶部日期 + 表内维度切换 |
| 双口径 | 分段控件切换 | 顶部开关，全屏联动 | **并排出两列，不切换** |
| 矩阵底色归一 | 全局（看绝对量级） | **按渠道各自归一**（看渠道内结构） | 无底色，行内 mini bar |
| 下钻 | 维度分段（商品/品类） | 点图元 → 右侧抽屉 | 表内换维度 |
| 代价 | 翻页多、信息稀疏 | 实现最重、信息密度高 | 图表弱、不适合汇报

## Resolution

**2026-08-11 定：走 D「图表优先单屏」。** 用户判据两条——「主要以图表为主」「比较好看」。据此 A（分页控制台）出局：一页一主题信息太稀、翻页多；C（运营台账）出局：表格优先与「图表为主」正面冲突。B 方向对但仍用表格承载矩阵，故做精修版 **D** 并定为落地形态。

### 补充需求（同日）：图/文双形态

用户追加：「各个板块优先以图表显示，图表右上角一个小 icon，点击即可查看文字版」。已实现为**每张卡片独立的图 ↔ 文字明细切换**，切换态写进 URL（`?txt=funnel,share,heat`），刷新与分享都保得住。这条解决了「图表好看但看不到准确数字」的老矛盾——默认全是图，要数字时逐卡翻，不需要为此另做一套报表页。

### B4 / B5 照此实现

- **布局**：单屏 bento（12 栅格），侧边收成图标条；数据中台不再拆成四个页面；
- **筛选**：顶部**全局筛选条**（日期粒度 / 渠道多选 / 订单数↔实发量口径），一处改动全屏联动，取代每页各自的日期选择器；
- **每张卡片两副面孔**：默认图，右上角 icon 切文字版明细（表格），状态入 URL；
- **图表清单**（全部对应 ECharts 标准类型，B5 直接映射）：

  | 卡片 | 原型实现 | ECharts 对应 |
  |---|---|---|
  | 订单 / 发货趋势 | 平滑面积图 + 渐变 + 末点高亮 | `line` + `smooth` + `areaStyle` |
  | 履约漏斗 | 梯形逐段插值上色 + 环节通过率 | `funnel` |
  | 渠道构成 | 按天堆叠面积 | `line` + `stack` + `areaStyle` |
  | 渠道占比 | 甜甜圈 + 下方占比条 | `pie` + `radius:['60%','80%']` |
  | 渠道 × 商品 | 热力色块矩阵 | `heatmap`（原型用 CSS grid，B5 换 ECharts） |
  | Top 商品 | 横向条，**按品类着色** | `bar` + `itemStyle.color` |
  | 积压构成 | 堆叠面积 | `line` + `stack` |

- **只保留一处常驻列表**：「需人工介入」队列——那是操作对象不是统计量；其余表格全部退到 icon 后面；
- **两个坑，B5 别再踩**：
  1. 热力图**按各渠道自身归一**，别用全局归一——彩食鲜量级压过其余三渠道，全局归一会让企业微信整列发白，等于没有信息；
  2. 履约状态**别把「已出库」和其余四态放一张堆叠图**——已出库占九成以上，会把积压压成看不见的细线。拆出「积压构成（不含已出库）」，已出库的量走漏斗与 KPI；
- **下钻**：点热力色块 / 点渠道占比条 → 右侧抽屉，展示映射（京东 SKU / 该渠道商品名 / 包装数量）与 SKU 上钻；组合品则展示 BOM 提示；
- **KPI**：六张卡（订单数 / 实发量 / 待出库 / 异常 / 缺货 / 回传失败），卡底压一条 sparkline，带环比。

A / B / C 三个变体连同切换条留在分支 `claude/prototype-design-50af32` 作为一手材料，**不进 main**。
