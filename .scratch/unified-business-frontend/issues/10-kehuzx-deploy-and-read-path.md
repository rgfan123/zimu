# 10: 客户中心对端部署与读路径通电

**What to build:** 客户中心的服务端在生产机上跑起来，履约中台与它建立专用内网连接，先只开**读**路径：客户跟进页能真正核对来自客户中心的客户档案事实，读取留下存证。

部署基准已定案：以本方 fork 分支为准。判据是对方主干（按 2026-08-25 的本地快照）没有任何对接提交，而生产 compose 编排本身也只存在于 fork 分支上，对方主干无可部署基准。若后续网络恢复且对方主干已合入，再评估切换。

密钥必须各不相同：系统会主动拒绝「一把钥匙当两把用」，配错时通路直接不就绪。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 客户中心服务端在生产机上运行且健康
- [ ] 两侧挂在同一专用内网，该网络不对外暴露
- [ ] 读路径所需的各把密钥分别签发且互不相同，长度满足要求
- [ ] 履约中台开启客户中心接通开关，并把客户跟进模块加入 MCP 开放清单
- [ ] 跑通一单：客户跟进页发起核对后，读取存证落库且页面呈现来源标注
- [ ] 「客户跟进」菜单在通电后按票 04 的机制自动出现
- [ ] 写路径此时仍关闭
