# 07: 原料库存上游长出 HTTP MCP 面并注入非默认密钥

**What to build:**（**跨仓：原料库存仓，不在本仓内**）原料库存服务当前只有 stdio 传输，只能靠在宿主机上 `docker exec` 进容器来调用。履约中台的后端运行在容器内，若走这条路就必须挂载宿主机的 docker socket，等于把宿主机的容器控制权交给应用容器——不可接受。

因此上游需要暴露一个可从容器网络访问的 HTTP MCP 端点。同一次变更必须一并注入非默认密钥：当前部署跑在源码里写死的占位密钥上，且经查证没有任何环境变量或 env 文件覆盖它。现在挡住风险的只是「没有 HTTP 面 + 零监听端口 + 无用户记录」这三重巧合，**HTTP 面一旦长出来，这三重巧合同时失效**。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 原料库存服务暴露可从容器网络访问的 HTTP MCP 端点
- [ ] 端点只在内部网络可达，不对公网暴露
- [ ] 密钥来自部署期注入，源码内的占位默认值在未注入时导致启动失败而不是静默使用
- [ ] 既有 stdio 接线在切换期间保持可用或有明确的切换窗口，网关问答不中断
- [ ] 有一次从履约中台后端容器内发起的连通性验证记录
