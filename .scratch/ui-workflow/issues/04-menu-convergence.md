# 04 — 菜单入口收敛与准入规则

**What to build:** 给菜单定一条准入规则并据此收敛，让入口数量长期可控。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

## 现状

9 个一级板块、**34 个可见入口**。作业中心从设计时的「仅高频运营入口（6 个）」涨到 **8 个**——其中两个是最近才加的（出库信息对账、采购比价）。

菜单一直在长，但没有人在收。

## 本票的重点是规则，不是删几个

一次性删掉几个入口没有意义，半年后会涨回来。本票要产出的是**一条可执行的准入规则**（例如：一级板块只放日常高频动线，低频查询进二级；某入口连续 N 周无访问则降级），并据此完成一次收敛。

规则要写进文档，让后续加菜单的人有据可依。

## 验收标准

- [ ] 产出一条可执行的菜单准入规则并写入文档
- [ ] 据规则完成一次收敛，被降级/移动的入口逐个说明理由
- [ ] 收敛后所有原入口仍可达（降级不等于删除），旧路径不 404
- [ ] 导航相关测试更新并全绿
- [ ] 规则与既有的业务对象边界（CONTEXT.md）不冲突
