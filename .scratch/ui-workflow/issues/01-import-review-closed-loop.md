# 01 — 导入到复核的闭环

**What to build:** 导入一个含待复核行的文件后，运营能**全程不碰左侧菜单**走完「上传 → 复核 → 确认本批次」。今天这条动线在代码里是断的，每处理一条待复核就要重走一遍循环。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

## 现状（已核实，不必重新排查）

一次导入的真实操作是：上传 → 看到「2 行待复核」→ 点「前往人工复核」→ **落在全局队列自己找是哪两条** → 处理完从菜单爬回文件作业 → **页面空白、批次没了** → 重新上传或重新找批次 → 才能点「确认本批次」。

断在三处：

1. **跳出去不带上下文**：文件作业页的按钮是裸链接 `<Link to="/workbench/reviews">`，不携带批次。
2. **复核页没有「批次」这个概念**：`ManualReviewPage` 里 `批次`/`batch`/`import_batch` 命中 **0 次**；筛选维度只有事项类型/责任团队/状态，没有一个能把人带回刚才那一批。
3. **批次状态是本地 state**：`const [result, setResult] = useState<ImportBatch | null>(null)`，不在 URL 里，返回即清零。复核页里也没有任何回文件作业的链接（命中 0 次）。

**好消息**：后端 `review_cases` 表已有 `import_batch_id` 外键，**数据是现成的**，缺的是查询参数与界面。

## 验收标准

- [ ] 批次标识进 URL，刷新与浏览器回退不丢当前批次
- [ ] 复核列表支持按导入批次筛选，且该筛选进 URL 可分享
- [ ] 从导入明细跳复核时携带批次上下文，落地即是该批次的待复核项
- [ ] 复核页有明确回到该批次的路径，不依赖左侧菜单
- [ ] **行为验收**：导入一个含待复核行的批次，全程不使用左侧菜单，能走完「上传 → 复核 → 确认本批次」
- [ ] 批次不存在或已确认时给出可读状态，不是空白页
