# UI 动线加固：实施地图 map

Type: map
Status: charting

## Destination

把界面从「每一页都是一张可筛选的表」变成能带着人把事做完的工作台：报警的地方能交接到处理的地方，跨页动线不断，页面不再继续膨胀。

## Notes

- **问题来源**：2026-08-20 对收敛分支的实测复查（导航 34 个可见入口、53 个页面文件对 7 个共享组件、工作台 292 行仅 1 个跳转、导入动线三处断点）。
- **与既有票不重复**：详情改真实路由（#62）、筛选进 URL（#63）、拆分人工复核页（#64）、URL 层级对齐（#61）已各自立票，本 effort 不覆盖。
- **核心判断**：早先的设计审计报的是单页属性（详情没 URL、筛选不进 URL），都对但都不解释用户的真实痛感。痛在**跨页动线**——单看每页都合理，连起来就断了。这类问题只有真的走一遍业务流程才看得出来。

## 优先级

**01 优先于其余三张**：导入是每天都在发生的动线，三处断点叠加导致「每处理一条待复核就要重走一遍循环」。这是持续损耗，先止血。

02/03/04 无依赖，可并行。03 是 prefactor 性质——它做完，后续所有页面改动都更便宜。
