# 02 — 接收并查看企业微信文字消息

**What to build:** 让配置业务群中的企业成员把普通微信群文字转发给企微 API 机器人后，系统可靠保存原始消息并固定回复“已接收”，运营人员能够从现有管理后台查看该消息证据；这一切不触发意图识别或业务成单。

**Blocked by:** None — can start immediately.

**Status:** resolved

- [x] 企业微信 URL 验证与加密消息回调通过公共 HTTP 工作，Token 和 EncodingAESKey 只从秘密配置读取。
- [x] 只有配置的企微主体、机器人连接和业务群进入业务消息存储；其他群不进入后续处理。
- [x] 回调保存企微消息 ID、会话、发送企业成员、消息类型、原始内容、协议提供的引用类型/内容、接收时间和受控原始载荷引用；不猜测协议未提供的父消息 ID。
- [x] 同一连接作用域内的重复消息 ID 只保存一次并只形成一次接收处理；不同消息 ID 的相同内容分别保留。
- [x] 消息安全保存后立即固定回复“已接收”，响应不包含草稿号、客户、商品、地址或处理结果。
- [x] 现有管理后台提供受权的消息列表/详情视图，能够查看原始文字证据且不直接渲染未知 JSON 或秘密。
- [x] 使用固定协议样本和真实 PostgreSQL 的 HTTP 验收覆盖验签失败、非业务群、首次回调和重复回调。

## Answer

已完成企微智能机器人 Webhook 的 URL 验证、加密 JSON 回调、业务群白名单、事务幂等保存和固定加密回复“已接收”。接收层只写入不可变的 `channel_messages` 证据并提供受权列表/详情 API，没有调用意图识别、订单识别或成单逻辑。Nginx 只对签名回调关闭 Basic Auth，管理 API 仍需认证；密钥只从部署配置读取。

后台新增只读“企微消息”页面，详情按所选消息 ID 守卫，避免切换记录时串显旧原文。协议不提供稳定的被引用消息 ID，因此只保存引用类型/内容，不按文字猜关联。固定加密样本 + 真实 PostgreSQL HTTP 测试、前端 22/22、生产构建、后端全量 54 个测试和 Java 21 镜像构建均通过。真实企微后台配置、业务群回调及 1 秒时限仍属于票 13 的外部端到端验收门禁。
