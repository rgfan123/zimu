## 设计结论（用户已认可的形态）

- **第一层：三张独立平台卡片**，每卡展示：可回传批次数 / 已跳过（有 blocker）/
  结果不确定（须先对账）/ 今日已完成 / 最近成功时间 / 平台状态
  （正常/凭据异常/未接入/暂不可用）。每卡一个按钮「查看并回传 N 批」；
  单平台不可用只禁用该卡按钮，**不阻断其他平台**（用户 8/24 明确：
  「每个平台单独点 并且不要影响一个阻断全局瘫痪 一个阻断就先skip」）。
- **点击后：确认抽屉自动取最新校验**（不要「先检查再确认」两连点）。
  两区：「本次将回传」（批次号/订单与行数/份数合计/运单完整度 12⁄12/物流映射/
  回填版本/平台是否已有相同结果）与「本次自动跳过」（批次号 + 明确原因 +
  下一步去处：缺运单→运单复核、无物流映射→承运商配置、未发完→等履约、
  多次发货→人工、版本作废→用新版、平台已有不同结果→对账、结果不确定→禁重发）。
- 底部唯一外部写按钮「确认回传 N 批」；服务端提交前复检，新 blocker 自动转
  SKIPPED，其余继续。
- 收件人/电话/地址/商品明细放批次详情抽屉，列表只展汇总（防宽表 + 防 PII 泄漏）。
- **结果持久化在页面**（不是 toast）：每批终态 = 已完成（平台写入且复查一致）/
  已跳过（未调平台）/ 已失败（平台明确拒绝，可修后重试）/ 待对账（超时或不确定，
  禁直接重发）。
- 中汇单独一张「Excel 待导出」卡片。
