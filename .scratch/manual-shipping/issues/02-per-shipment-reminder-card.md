# 02 — 运单回传提醒卡改成「一单一卡」，并支持引用回单号

**What to build:** 催回传的企微卡片按**发货单**发，不按导出批次发；卡上写清是谁的什么货；用户引用这张卡回一个运单号，系统就能把号落到那张单上。

**Blocked by:** 01（人工录入运单的内核）—— 本票的引用解析最终要调它

**Status:** open

**Claimed by:** —

---

## 现状：卡片只说了一串号

生产实测的卡片正文（`channel_messages` id=29 的 `quote_content`）：

```
【运单回传提醒】
导出批次 EXP-81B506EFC0CE4A75A3B8AB0B7D6D7A43（第三方履约）已等待约 2880 分钟，仍有 1 个发货批次未回传运单。
请履约方在群内回传填写后的导出文件（含快递公司与运单号）；如已回传请忽略本提醒…
```

用户原话：「我只能看到批次，但不知道订单详情是哪个，不知道对应哪个订单」。

那串 EXP 号背后其实是一张很具体的单：

```
shipment 18 / SHIP-C31B7C0D…  订单 ORD-0225AD95…
收货人 谭华勇   子牧雷山黑猪套餐1800g   文件「子牧猪肉8.27发货清单.xlsx」
```

**这些人看得懂的东西一个都没印在卡上。**

## 已验证的能力：引用卡片能拿回全文

2026-08-29 17:57 生产实测（`channel_messages` id=29）：用户引用那张卡、回了 `SF5152783768751`，落库结果：

```
message_type = text
quote_type   = text          ← 卡片被引用回来算「文本」
quote_content = （卡片全文，含 EXP-81B506…）
content      = SF5152783768751
```

企微 aibot 的 `quote` 已经在解析（`connector/wecom/WecomMessageDispatchHandler.java:141-145`），字段也已落库（`channel_messages.quote_type` / `quote_content`）。

**但 `quote` 里没有任何 msgid**（对比：引用文件时 `quote` 只有 `{msgtype, file:{url, aeskey}}`，见 id=22 的 `raw_payload`）。所以**唯一可用的锚点就是卡片正文里印的标识**——卡上印什么，引用回来才能解析出什么。

## 设计决定：一单一卡（用户已选定）

唯一性**由构造保证**，不靠解析猜。

明确否掉的方案：卡片列 N 张单、用户回 N 个号、按顺序配对。文件链路当年就特意否掉过行序匹配——`file/TrackingFileService.java:427` 注释原文：「行匹配按（出库单号+品名+数量）配对而不是按行序：人会排序、会插行」。

**猜错的后果不是少发一单，是客户 A 收到客户 B 的运单号**，且系统里一切正常、无任何报错，发现时已是客诉。

## 验收标准

- [ ] 催回传卡按 Shipment 发，一张单一张卡
- [ ] 卡上印出人能认的信息：收货人、商品、出库单号；同时印出机器能解析的稳定标识（出库单号即可，它是系统签发的稳定业务号，每行都有——见 `TrackingFileService.java:375-377`）
- [ ] 引用该卡 + 回复运单号 → 解析出目标 Shipment 与单号 → 调 01 的人工录入内核 → 产出草稿进复核队列
- [ ] **解析不出目标就明确拒绝并回话说明**，绝不猜、绝不落
- [ ] 回复里含多个运单号 → 拒绝并说明「一张卡一个号」
- [ ] 一张卡对应的 Shipment 已经有运单 → 回话说明已回传，不重复落
- [ ] 快递公司从运单号前缀推断时必须命中承运商字典（`carrier_prefix_mappings`），推断不出就要求补充，不默认
- [ ] 用例覆盖：正常回填、解析失败、多号、重复回填、承运商推断失败

## 注意

企微卡片有长度上限（见 `docs/adr/0014-wecom-broadcast-cards-button-interaction.md`）。加了收货人和商品之后要核实不超限；超了优先保商品名与出库单号，收货人可只留姓。

**收货人姓名属于 PII**：催回传卡是发给履约方群的，履约方本来就要照着单发货、看得到收货信息，所以印姓名不算越界。但**不要**把电话和详细地址印进卡片——那两样在导出文件里已经给过了，卡片是催办不是派单。

## 硬约束

- 不碰生产数据，不部署
- 中文文案，说人话——用户对现在这张卡的评价是「不说人话」
