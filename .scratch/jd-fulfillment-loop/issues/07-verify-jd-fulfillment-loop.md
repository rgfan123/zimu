# 07 — 验证京东履约闭环与真实环境门禁

**Type:** implementation

**What to build:** 团队可以用一套可重复的 Mock 验收证明从请求预览到运单回填的完整闭环，并独立记录真实查询权限与真实写操作门禁，不把本地测试或查询成功冒充生产建单能力。

**Blocked by:** 06 — 幂等回填京东运单与履约进度

**Status:** claimed

**Claimed by:** codex-root

- [ ] 一条命令在 Mock JD 与真实数据库上验证多行 Shipment 的预览、SKU 门禁、库存、幂等建单、运单回填、状态、ReviewCase、事件、版本和审计。
- [ ] 普通测试套件在没有 JD 凭据时完整通过，且不会访问任何外部 JD 接口。
- [ ] 真实只读探针仅覆盖商品、库存和出库单查询，输出目标身份、验证时间、请求 ID、业务码与数据存在性，不输出凭据或 PII。
- [ ] `addSoOrder` 明确排除在“只读探针”之外；真实写验收需要用户单独授权、指定测试 Shipment/订单、确认目标环境和后续取消或运营处置方案。
- [ ] 外部权限按已验证、未授权、缺配置或未验证分别记录；Mock 成功与真实权限结论分开展示。
- [ ] 在所有消费者迁移后清理不再使用的 Fulfillment 级 JD 字段或兼容路径；若旧迁移尚未发布，则在发布前直接纠正并验证全新安装。
- [ ] 最终回归同时覆盖 Excel 回退路径，证明 JD API 闭环未破坏既有履约和来源回填行为。
