# Spec — 采购比价：价格情报层 + 工单最小商业化

**Effort slug**: `procurement-price`
**决策依据**: ADR 0007（范围）/ 0008（建议规则与盯盘清单）/ 0009（采集运行时）/ 0010（建议与工单的关系），位于 issue-103 worktree `docs/adr/`。同事 Demo（牛羊肉采购比价 Agent，FastAPI+Playwright）为移植素材来源。
**基线事实（2026-08-23 库内核实）**: `procurement_tickets` 无供应商/价格字段、`procurement_receipts` 无附件字段、工单总数 0；全库无价格表；`procurement-price-agent` V2 active 但 0 次运行；企微收件链路完整、业务级主动推送不存在（仅 sendFrame 原语）。

---

## Problem Statement

采购员每天要决定"缺的品今天向谁买"。价格情报散在两个需要登录的行情网站（牧集、肉交所）里，靠人每天手动翻页、心算剔除虚标价，看完就忘——没有落盘、没有历史、没有和缺货工单的对照。系统里的采购工单只记"缺什么"，不记"最终向谁、按什么价买了"，到货也不留凭证——买贵了没人知道，货到了手续齐不齐没人管。

## Solution

每天早上系统自动扒两平台白名单厂的报盘，统一换算落盘；按"剔极值、荐中间"规则对盯盘品生成建议（被剔除的也展示并给理由）；建议在采购工作台与缺货工单相遇——有缺货的品一键跳工单，处理工单时参考价在旁、成交价手填；确认到货必传凭证。价格建议与实际成交从此都在系统里，可复盘。

## User Stories

### 盯盘与采集

1. 作为采购员，我想在系统里维护"每天要盯哪些品"的清单，这样不用改配置文件找工程师。
2. 作为采购员，我想每天早上打开采购工作台就看到当天扒好的价格，这样不用自己登两个网站翻页。
3. 作为采购员，我想在盘面陈旧时看到"数据是 X 月 X 日的"，这样我不会把昨天的价当今天的用。
4. 作为采购员，我想在采集失败时看到失败原因（会话失效/页面改版）和上次成功时间，而不是空白或旧数装新，这样我知道要找人重新登录还是等一等。
5. 作为采购员，我想随时手动点"立即更新价格"再扒一次，这样盘中波动大时能看到最新价。
6. 作为运营，我想采集失败自动进告警中心，这样不用每天有人专门检查爬虫活没活着。

### 建议与剔除

7. 作为采购员，我想每个盯盘品的建议告诉我"推荐哪家厂、什么价、比昨天涨跌多少"，这样电话询价有个锚。
8. 作为采购员，我想看到被剔除的最高/最低报盘和剔除原因，这样我知道 AI 没有藏牌，极端价我自己能核。
9. 作为采购员，我想在报盘不足 5 个时看到"样本不足，未剔除极值"的标注，这样我知道这天的建议参考性有限。
10. 作为采购员，我想对建议点"已知情"或"驳回"，这样处理过的建议不再干扰我，且系统记得我的判断。
11. 作为采购员，我想看到每条建议的运行留痕（哪次运行、什么时候），这样出问题能追溯到那一次采集。

### 建议 × 缺货工单

12. 作为采购员，我想建议卡上直接显示"该品有 N 张待处理缺货工单"并能跳过去，这样情报和任务对上。
13. 作为采购员，我想在处理缺货工单时旁边看到该品当日建议参考价（只读），这样电话核价不用切页面。
14. 作为采购员，我想在工单上填写最终选定的供应商和电话确认后的实际成交价，这样系统记得这单向谁按什么价买的。
15. 作为采购员，我不想系统把建议价自动填进成交价字段，这样虚标价永远进不了成交记录（比价价≠订单价）。

### 到货凭证

16. 作为采购员，我想确认到货时必须上传海关手续/检疫凭证图，这样"货到了但手续没到"的单进不了账。
17. 作为财务，我想在回执上看到凭证图，这样对账时能核验每一单的手续完整性。

### 留痕与边界

18. 作为管理者，我想 Agent 的每次采集与建议生成都出现在 Agent 运行记录里（含手动触发），这样自动与人工同标准留痕。
19. 作为管理者，我想价格建议永远不能自动创建工单或修改任何业务事实，这样确定性业务结果始终由人产生。
20. 作为采购员，我想"建议参考价"和"实际成交价"分开保存，这样将来能复盘采纳率和省了多少钱。

## Implementation Decisions

- **D1 数据层（新增三表 + 两处扩列）**：报盘表（append-only：平台/厂号归一化值/品名/原始价格文本/换算后元每千克/采集批次/采集时间；换算失败保留原文标"待核"）；建议表（每品每日一条：推荐与次选、对昨日涨跌、剔除明细及理由、样本量、处置状态 待处理/已知情/已驳回、agent_run 引用）；盯盘品表（品名、启用态、维护留痕）。`procurement_tickets` 增列 供应商、实际成交价；`procurement_receipts` 增列 凭证附件引用（复用 ContentAddressedFileStore）。
- **D2 采集通道**：两爬虫移植为 `scripts/` 下 Python 脚本（Playwright），凭据与会话材料在 `data-local/`（0600），按 `PlatformScriptRunner` 既有模式由后端执行；每日 08:00 调度 + 手动触发端点（不限频，用户拍板）。会话失效不自动重登（防风控），人工跑交互式登录脚本恢复。
- **D3 建议引擎纯规则、零 LLM**（沿用 Demo ADR-008 的"规则锁死"）：报盘 ≥5 各剔最高最低 1 个、<5 不剔标注；推荐中间带最低价厂+次选+对昨日中间价涨跌。数值计算不经过任何模型。
- **D4 Agent 留痕挂既有设施**：每次采集+建议生成记为 `procurement-price-agent` 的一次 agent_run（含手动触发），复用 AgentRuntimeFacade/JdbcAgentObservability，不新建留痕机制。
- **D5 建议不产生任何写副作用**（ADR 0010）：不创建工单、不预填价格；工单唯一来源仍是缺货。建议卡动作 = 已知情/驳回/跳该品缺货工单。
- **D6 回执凭证为必传校验**：确认到货缺凭证附件即拒绝（对齐 Demo ADR-005"所有单必传"）。
- **D7 失败呈现**：采集失败 → 运营告警 + 工作台价格区诚实态（原因+上次成功时间），页面继续显示最近成功数据并标日期。
- **D8 企微推送本期不做**：待 #90"业务事件主动通知"机制落地后，将"每日价格建议"注册为事件类型接入；不另造推送通道。
- **D9 前后端契约先行**：建议/报盘/盯盘品查询端点的响应形状在后端票落地时评论钉死，前端只消费；施工分界按 PLAN（后端 Agent 不碰 frontend/）。

## Testing Decisions

- **后端接缝 = API 集成测试**（既有 Spring 测试设施）：剔除规则全分支（≥5/=5/<5/并列极值）、单位换算移植正确性（元每吨→元每千克、无单位拒算标待核、防 1000 倍）、厂号归一化（SIF4333/4333厂/纯数字）、建议处置状态流转、回执缺凭证被拒、工单商业字段写入。
- **爬虫用离线夹具测**：录制两平台页面 HTML 作 fixture，解析器对夹具断言；真实登录采集属人工验收，不进 CI。
- **前端接缝 = routeHarness 路由级测试**（沿用 #103 单一接缝）：建议卡渲染（含剔除展示/样本不足标注/涨跌）、已知情/驳回动作、缺货工单联动跳转 URL、参考价只读展示、陈旧数据日期标注、采集失败诚实态。
- 契约：建议卡上"N 张待处理缺货工单"计数与跳转后列表同接口同筛选（ADR 0006 同款原则）。

## Out of Scope

- Demo 的下单/入账/库存/LLM 对话入口（子牧已有或违红线）；金额汇总与对账（Phase 3）；自动下单/自动改任何业务事实；企微推送（依赖 #90，见 D8）；建议采纳率/节省额复盘报表（数据从本期开始积累，报表另立票）。
