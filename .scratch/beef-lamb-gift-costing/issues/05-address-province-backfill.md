# 05 — 地址→省份解析与历史订单区域回填

**Type:** task
**Status:** open
**Blocked by:** —

## Question

决策 8 要求「没传省份就按客户历史订单省份分布推断」。但 `app.orders.receiver_address` 是自由文本 TEXT，**库里没有省份**，这条路现在走不通。本票把它打通。

结构化 province/city 目前只存在于 `ShipmentJdReceiverAddressCommand`（京东出库的临时入参），不落库。

### 要做的

1. **确定性省市前缀表**：34 个省级行政区 + 常见简称与别名（「内蒙」/「内蒙古」/「广西壮族自治区」/「新疆维吾尔自治区」…）。落成主数据还是资源文件，由实施时定。
   - **红线**：解析必须确定性，**不得调用模型**。运费是钱，不能有幻觉。
2. **解析器**：`receiver_address` → `province`（+ 尽力而为的 city）。命中不了的**不猜**，标为未解析并进复核，不得默认某个省。
3. **落库**：`app.orders` 加 `receiver_province` / `receiver_city`（可空）+ 解析来源标记（PARSED / PROVIDED / MANUAL）。新订单入库时解析，人工可修正。
4. **历史回填**：一次性回填存量订单，产出回填报告——总数、命中率、未解析样本清单。**命中率与未解析样本必须报出来**，不许静默跳过；票 09 的区域画像可信度直接取决于这个数。
5. **验收**：抽样人工核对；对 `彩食鲜` 这类已知集中在特定省份的客户，回填后的分布应与业务认知一致（用户提到彩食鲜总部在福建、福建订单多，可作为对照）。

### 与其他票的关系

- 票 09（客户区域画像）直接依赖本票的回填结果与命中率。
- 本票是 AFK task：没有要决策的东西，全是执行；但**回填是写历史数据，需先在非生产库验证并出报告，再决定是否对生产库执行**。
