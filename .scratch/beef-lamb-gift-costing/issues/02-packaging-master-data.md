# 02 — 包材、装箱方案与耗材主数据

**Type:** grilling
**Status:** open
**Blocked by:** —

## Question

决策 5 把「包材自重、箱内外径与体积、冷媒重量」归到包材主数据，礼包毛重与体积运行时按装箱方案算。这张表怎么建，装箱方案怎么表达？

装箱方案不是记账细节，它**直接决定运费档位**：6 号泡沫箱 435×300×250 = 32.6L，按抛重系数 6000 折 5.44kg，已超过净重 3.8kg；5 号箱 385×255×215 = 21.1L 折 3.52kg。选哪个箱子，计费重量差近 2kg。

### 现状与数据缺口

- Excel `包材` sheet **只有 5 行**（大/小金色贴体盒、200g/300g 黑盒、1kg 大白盒），且**没有重量列、没有体积列**。
- 京东 B2C 冷链价格表提供了另一套按件计价的耗材（全档已转录到 `input/jd-b2c-cold-chain-price-table.md`）：冷藏冰袋250g 0.2 / 冷冻冰袋250g 0.3 / 干冰500g 0.9；泡沫箱 1~6 号（0.9 / 1.7 / 2.1 / 2.9 / 4.5 / 5.5）；保温袋 2~6 号（0.5 / 0.6 / 0.7 / 0.8 / 1.1）。**有尺寸有单价，但同样没有自重**。
- 自有包材（盒/袋/贴纸/腰封/膜/签）与京东耗材（泡沫箱/保温袋/冷媒）是两个来源、两套计价，但在成本里是同一类：按件直接材料。

### 待决策点

1. **一张表还是两张**：自有包材与京东耗材合并为统一的「包材主数据」（用供货来源区分），还是分开建？合并的好处是装箱方案可以混搭（自有内盒 + 京东泡沫箱）。
2. **必补字段**：`自重g`、`内径长宽高mm`、`外径长宽高mm`、`体积L`（可由外径推导）、`单价`、`供货来源`、`适用温层`。这些数据 Excel 里没有——**谁来补、补到什么精度**？是否允许先按类型给默认自重、标记为估算值？
3. **装箱方案的表达**：是 (A) 主数据里预置若干「装箱方案」（箱型 + 冷媒种类与数量 + 内包材），礼包引用一个方案；(B) 运行时按礼包体积/重量/温层自动选箱，方案是计算结果不是主数据；(C) 两者结合——自动推荐 + 可人工指定覆盖。
4. **冷媒用量规则**：冰袋/干冰要几个，取决于温层、运输时长、季节。这是规则还是人工填？一期是否简化为「按箱型给固定用量」？
5. **装得下判定**：礼包 8 件能不能塞进 5 号箱，需要件级尺寸（Excel 没有）。一期是否退化为「按体积估算 + 人工确认」，不做真实装箱求解？
6. **决策 9 的边界确认**：耗材与订单生产费计入礼包成本（默认值），存储费排除。resolve 时请顺带向用户确认这条，见 map 决策 9 的 ⚠️ 标注。
7. **票 14 已提供的真实证据（`../research/14-invoice-reconciliation.md`），本票可直接采用**：
   - 13 个耗材 SKU（泡沫箱1~6号、保温袋2~6号、冷媒3种）的价格表单价**已被三个月账单 2139/2139 行精确验证**，不需要重新核价。
   - **箱型与保温袋型号强绑定**——753 个订单里，用 N 号泡沫箱的几乎全部配 N 号保温袋（仅 1 例外），说明"选箱"和"选保温袋"是**一个决策不是两个**，待决策点 3 的装箱方案设计可以直接把两者绑定，不必分开建模。
   - **耗材量与包裹重量的量化关系，账单数据不支持**：`仓储服务费-冷链`（耗材明细）没有商品重量/体积数据，也没有能跟运费明细（不同单号体系：`JDVA...` vs `ESL...` vs `614_2253_EMG...`）关联的公共键，无法从账单反推"每 kg 配几个冰袋"。待决策点 4（冷媒用量规则）**没有真实数据可用，只能走人工经验规则或另找数据源**，不要指望账单能补这块。
