## 1. 导航树与设计意图对照

设计意图（`.scratch/business-object-navigation/issues/01`）：
- 作业中心 = 仅高频运营入口：人工复核、渠道消息、履约任务、采购协同、文件作业、发货记录
- 低频京东连接/基础资料/原始查询 → `系统管理 → 京东工具`；履约方配置中立入口在系统管理
- 订单中心「全部订单」= 唯一总订单入口，京东专业单据**不计入**总订单（issue 04）
- 库存中心 = 可信总库存 + 下钻明细（issue 02/03），不为每类原始查询建菜单
- 业务对象边界（CONTEXT.md）：订单/履约/采购/主数据（商品·品类·SKU）/系统配置/渠道消息互不混淆

## 3. 可疑项（2 处，均非整页错放）

### 3-1 ⚠️ 经营分析页内混入「需人工介入」功能块
- **证据**: `output/playwright/layout-audit/经营分析/经营分析.png`；页面第 8 个 BentoCard 标题「需人工介入」，空态文案「暂无待介入事项」（`frontend/src/pages/analytics/AnalyticsPage.tsx:782-808`）
- **问题**: 「需人工介入」是**作业中心/人工复核（ReviewCase）域**的操作性待办清单，混在指标分析（趋势/漏斗/构成/热力图）页内，与经营分析"看数"语义不符——用户反馈"不同板块被放在一起"最可能指向此处
- **建议归属**: 移到**工作台**（与 `工作台` 现有「待人工介入明细」合并，消除重复），或在经营分析内仅保留计数指标、去掉可操作的介入清单；若确需保留，建议用「关注事项」类标签并标注跳转链接到人工复核，避免同一概念两处呈现

### 3-2 ⚠️ 主数据板块名与页面文案口径不一致（「商品中心」）
- **证据**: `output/playwright/layout-audit/作业中心/文件作业.png`；文件作业页提示文案「…请在**商品中心**维护 SKU 映射」；侧边菜单该板块名为「主数据」
- **问题**: 「商品中心」是旧导航命名残留，与现板块名「主数据」口径不一，用户会困惑 SKU 映射到底在哪维护
- **建议归属**: 纯文案修正——把「商品中心」改为「主数据」或「商品档案」，保持菜单-文案统一（CSS/文案层改动，不影响路由）

## 4. 观察备注（不构成问题）

- URL 前缀与菜单归属解耦是 issue 01 的刻意设计（`/fulfillment/*` 同时服务于作业中心与系统管理/京东工具），旧书签兼容 ✅
- 「文件作业」菜单名比页面实际标题（来源订单导入 / 履约导出）宽泛，属概括命名，不判为错放；如追求菜单-标题严格一致可考虑改名
- antd `destroyOnClose` 弃用 Warning 与 Descriptions span Warning 为版本噪音，不影响布局
- 全部 30 页渲染无 console error，隐藏页均可直达（URL 可访问性满足 issue 01 要求）
