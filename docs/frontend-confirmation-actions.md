# 前端「确认动作」三形态规范

> 依据：GitHub issue #43（「确认动作三形态规范 + 操作结果区收敛」）。
> 现状盘点与证据索引见 `.scratch/ui-ux-audit-fixes/ux-inflation-research.md` §1.3/§1.4。
> 本文件是所有「写操作前人工确认」的前端开发约定：新页面与既有页面修改都按此执行。

## 1. 为什么需要本规范

同一「写操作前确认」意图，历史上并存三种实现（Popconfirm / Modal / Drawer 内做写操作），
且 Modal 与 Drawer 内部各自内嵌说明 Alert，同一页面两种形态并存却没有任何文档约定
「哪种确认用哪种形态」（研究 §1.4）。本规范固定三形态的适用边界，堵住「弹窗叠弹窗」。

## 2. 硬边界：确认次数不减

不可逆写操作的人工确认是**业务硬需求**，不是冗余（CONTEXT.md：导入批次确认「不得拆成逐行或逐客户确认」、
履约导出「文件一旦生成即形成履约承诺」、复核事项「均不能由模糊匹配自动关闭」）。
本规范只统一**形态**，**不减少任何写操作的确认次数**：

- 禁止删除已有 Popconfirm / Modal 确认；
- 禁止把确认改成「无确认直接执行」；
- 只允许把确认从一种形态改为同权重的另一种形态（如 Modal → Drawer 内联表单），且仍保留
  等价的确认门槛（必填理由、影响说明、提交按钮）。

## 3. 三形态定义

### 3.1 行内轻量确认 → Popconfirm

- **适用**：单步、无附加输入、无需解释太多信息量的写操作（如关闭事项、删除单行、确认接收）。
- **做法**：
  - 影响说明写在 `title` / `description` 里（纯文字）；
  - 高危操作（关闭、取消、删除）的确认按钮用 `okButtonProps={{ danger: true }}`。
- **禁止**：Popconfirm 内再包 Alert（说明一律用 description 文字，不叠提示框）。

### 3.2 需理由 / 表单 / 多信息确认 → Modal

- **适用**：需要必填理由、表单输入（数量、备注、地址字段等）、或影响说明较长的写操作。
- **做法**：
  - 表单用 `Form` + `Form.Item` 校验，必填理由用 `rules={[{ required: true }]}`；
  - 影响说明放 **Modal 标题或正文**——正文用 `Typography.Paragraph type="secondary"`
    次级文字，不重复内嵌说明性 Alert；
  - 提交按钮保持 `confirmLoading` + 提交中禁用取消。
- **禁止**：Modal 内再嵌「说明 Alert」；说明与表单字段以外的错误反馈（如提交失败）仍可用
  错误 Alert 或正文错误文字（这是结果反馈，不是说明）。

### 3.3 大批量复核 → Drawer，但不在 Drawer 内叠 Modal

- **适用**：详情 + 大量行复核（明细表格、时间线、逐行证据），复核与写操作在同一上下文中完成。
- **做法**：
  - 写操作确认在 Drawer 内用「按钮 + 内联说明」或 Popconfirm 完成；
  - 需要表单输入的写操作（续发批次、取消缺口等）在 Drawer 内展开**内联表单区**
    （按钮切换展开/收起），说明文字与表单字段内联放置；
  - 内联说明可用次级文字（推荐）或说明性 Alert，保持单层。
- **禁止**：在 Drawer 之上再叠 Modal（弹窗叠弹窗）；Drawer 内的分支信息密度
  （按 action 分支的条件说明 Alert）不属于弹窗，**不得删减**，可考虑折叠但属于另一议题。

## 4. 操作结果反馈：页面底部固定「操作结果区」

- **问题**：操作结果一律走 toast，单页最多 27 处 `message.*`（SalesOutboundPage），
  toast 满天飞、页面主区反而空白（研究 §2.2）。
- **做法**：
  - 页面级操作结果（成功/失败反馈）收敛为页面底部固定的「操作结果区」：
    渲染最近一次操作结果（Alert 或自绘条），**不自动消失或长停留**，可手动关闭，被下一次操作结果替换；
  - 结果区与操作位置解耦（页面级操作适用；弹窗/抽屉打开期间结果区会被遮罩盖住，此时仍用 toast
    或弹层内联结果反馈）；
  - **保留 toast 的场景**：表单校验警告（在提交函数里提前 return 的提示）、loading 等中间态、
    必须即时反馈的闸门/边界错误（如渠道未接入）。
- 页面内的结构性结果展示（导入批次摘要、渠道拉取结果明细等）属于内联状态，不属于 toast，保留。

## 5. 判定速查表

| 场景 | 形态 | 要点 |
|---|---|---|
| 单步、无附加信息 | Popconfirm | description 纯文字，不包 Alert |
| 需必填理由 / 表单 / 多信息 | Modal | 说明放标题或正文，不嵌说明 Alert |
| 大批量复核 + 写操作 | Drawer | 内联表单或 Popconfirm，不叠 Modal |
| 页面级操作结果 | 底部结果区 | 不自动消失，可关闭，被下一次结果替换 |
| 校验警告 / 中间态 / 闸门错误 | toast | 保留，不入结果区 |
