# 三平台凭据轮换机制（ticket 12）

状态：2026-08-18 定稿
适用：彩食鲜 / 聚福宝 / 飞象 供应商后台账号（自动拉取/回传用）

## 为什么需要

- 三平台账号密码以明文存于 `data-local/*-credentials.txt`（gitignored，仅本地）
- 多份 HAR 含明文密码与**有效会话**（JWT/cookie）——会话劫持面真实存在
- 契约均无 SLA，账号被封禁的代价 = 接入链路整体停摆 + 人工导表兜底

## 轮换日程

| 项 | 值 |
|---|---|
| 周期 | 每 **90 天**（与平台会话/密码策略对齐，可调） |
| 责任人 | 运营（改平台密码）+ 开发（更新本地凭据文件并回归） |
| 触发条件 | 周期到期；凭据疑似泄露（HAR 外传、设备丢失、账号异地登录提醒）；平台强制改密 |

## 流程（一次轮换 ≈ 20 分钟）

1. **运营**：登录三个平台后台，修改账号密码（或平台强制）
2. **开发**：更新 `data-local/*-credentials.txt`（只改密码行）
3. **开发**：回归登录——跑三个脚本的登录段（`--dry-run` 或登录验证），确认新密码可用、token 续期正常
4. **清理**：删除/归档含旧密码的 HAR 副本（桌面 `*.har` → 本地归档或删除）；确认 git 无凭据泄漏（`git log -p -- data-local` 检查历史，必要时清历史）
5. **记录**：在凭据文件头部追加轮换日期；AuditLog 记 SYSTEM 主体

## 安全红线

- 凭据只走环境变量（脚本）或 `app.*` 配置（Java Connector 一期 env 注入）；**不入库、不入日志、不入 git**
- `data-local/` 与 `**/.env*` 已 gitignore；新机器克隆后需手动重建凭据文件
- 多平台**不要共用一个密码**；密码强度按各平台要求取最高
- 会话 cookie/JWT 的有效期：聚福宝 refresh 15 天、飞象 session 1 天、彩食鲜由登录接口续期——**轮换周期内自动续期即可，无需人工**
