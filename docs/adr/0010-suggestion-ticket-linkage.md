# Suggestions never create tickets; tickets are shortage-driven, suggestions are market intel

Grilling 2026-08-23（用户纠正："创建工单，不考虑预算，只考虑缺什么品"）。

## Decisions

1. **工单唯一来源 = 缺货**（子牧既有机制：履约缺货触发，记品与数量）。价格建议
   不创建工单，也不存在"价格好就主动囤货"的机会性下单入口。
2. **建议是独立情报**：每日生成，与缺货无关；两者在采购工作台相遇——
   建议卡联动显示"该品有 N 张待处理缺货工单"并可跳转；无缺货则建议仅供知情。
3. **原型建议卡动作条语义修正**：「创建工单」按钮取消，替换为
   「已知情 / 驳回 / 查看该品缺货工单（有则显示）」。已知情/驳回状态落库留痕。
4. **供应商与成交价在工单处理时人工填写**：工单处理页旁显示该品当日建议参考价
   （只读展示，不进任何字段）；采购员电话确认后手填实际供应商与成交价。
   「建议参考价」与「实际成交价」两个数分开落库，为将来复盘（采纳率/节省额）留据。
5. 同事 ADR-003（比价价≠订单价、AI 不碰钱）在本模型下完整成立且不再需要预填折衷。

## Considered options

- 建议卡一键创建预填工单：rejected —— 工单由缺货驱动，价格情报不构成采购理由
  （用户原话"不考虑预算，只考虑缺什么品"）。
- 预填建议价进成交价字段：rejected —— 虚标价可能溜进成交记录，违背 ADR-003。
