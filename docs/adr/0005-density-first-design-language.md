# Density-first design language: the first screen is the data, never an explanation

Grilling 2026-08-23（用户确认）："AI 味很浓、不好用"的病灶按命中程度：

1. **信息密度太低（命中）**——一屏一个大按钮加两句话，数据要点进去才看得到。
2. **文案是 AI 腔（命中）**——解释性 lede、满屏"当前未接入"说明。操作员天天用，
   这些话第二天就是噪音。
3. **视觉是模板脸（部分命中）**——大圆角卡片、大留白、居中 hero。

## Decisions

- **每个页面第一屏必须是可操作的数据本身**（表格 / 队列 / 数字），不是对功能的介绍。
- **解释文字全部降级**：lede 叙事句删除；"未接入/暂无汇总"类诚实态压缩为区块内的一行
  短标注（不占版面主体）；教育性说明移到 hover / title，不常驻屏幕。
- **按钮跟着数据走**：动作按钮附着在它作用的数据行 / 区块上，不再独立成卡。
- **骨架先行（skeleton-first）**：工作台页面先把原型的完整骨架一次立起来——发货台 =
  七指标 + 八段链路 + 复核分组 + 告警堆栈全部在位——缺数据的段位就地给一行短诚实态，
  然后逐段接数据。不再"有多少数据画多少区"（那正是薄版大按钮页的由来，用户明确否定）。
- 壳层（ADR 0004 的原型移植侧栏）保留，不在本次推翻范围内。

## Considered options

- 继续按票逐区块交付（先按钮、后链路、再复核）：rejected —— 中间态永远是一张
  "解释页"，用户两次看到的都是它；骨架不依赖数据，没有理由等。
- 保留 lede/说明文案以"降低学习成本"：rejected —— 高频生产工具的学习成本发生在
  第一天，之后所有解释都是密度税。
