# ADR 0013：受信模板合并放行自动成单与京东发货

- 日期：2026-08-27
- 状态：已接受
- 决策者：产品负责人、Codex

## 背景

现有来源文件只有命中固定平台指纹才会被解析；模板未识别时直接拒绝，Agent 既看不到工作簿证据，也不能创建订单。目标是在来源渠道可信但模板结构首次出现时提取订单候选，经一次人工确认建立可复用模板，并让后续同结构文件自动进入履约。

## 决策

首个模板未识别批次只生成来源订单候选批次，操作员确认整批时可额外勾选“信任此模板”，生成不可变、版本化的 TemplateProfile。模板信任使用一个总开关：同一版本后续批次全批通过确定性门禁后，同时自动生成 CanonicalOrder 并自动提交京东发货；不提供独立的 `auto_import` 与 `auto_jd_outbound` 授权。

来源渠道必须来自上传参数、连接器或群绑定等可信上下文，模型不得猜测。Sheet 结构、规范化表头或列顺序任一变化都形成新模板并重新人工确认。任一候选缺字段、SKU 多匹配、地址不确定或疑似重复时，整批禁止自动成单和发货，正确候选继续保留。任务采用持久化异步状态与内容哈希幂等；京东写入结果未知时进入 `RECONCILIATION_REQUIRED`，禁止盲目重试。

## 考虑过的方案

- 固定指纹未命中即拒绝：安全但无法吸收渠道模板变化，运营持续依赖开发补解析器。
- 自动成单与自动京东发货分开授权：影响面更小，但用户明确选择单一总开关，避免同一模板维护两套容易漂移的授权状态。
- 首次未知模板直接全自动：反馈最快，但没有受信映射作为独立证据，无法满足真实外部写的可追责边界。

## 影响与风险

- 合并开关扩大了错误模板映射的影响面：一次误信任可能从内部订单继续传播到真实京东写入。
- 风险通过显式模板信任、精确结构失效、整批硬门禁、操作人授权、幂等外部写、审计与可撤销信任共同控制；模型置信度不参与放行判定。
- 第一版只覆盖 Excel/CSV 与京东云仓；图片识别和第三方履约自动提交不在本决策范围内。
