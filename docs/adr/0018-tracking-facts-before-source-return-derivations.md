# ADR 0018：真实运单事实先提交，来源回传独立派生

Shipment 已确认的物流公司与运单号必须在独立事务中成为不可回退的 `Tracking` 事实；来源平台在线回传、来源回填文件生成和企微投递都是其后的可重试派生流程，通过持久任务或 outbox 推进。派生失败只能进入来源回传待处理、失败或对账状态，不得回滚 Tracking、实发数量或 Shipment 已发货事实。

来源承运商翻译只是内部 Carrier 到渠道展示名称或接口代码的适配，不是允许承运商白名单。文件渠道缺少专用翻译时默认使用内部标准名称；在线渠道也先用渠道翻译覆盖，缺失时用正式运单的标准名称或内部代码匹配平台实时字典。只有外部接口明确要求专用代码且实时字典或专用 API 代码都无法唯一解析时，才阻断该渠道的回传动作，并且阻断范围不得扩大到运单接收事务或同批其他已完成事实。

这一边界牺牲了“运单接收与来源回传同时成功”的单事务表面原子性，换取真实物流事实不被次要适配配置回滚，并使回传失败能够独立诊断、重试和对账。

HTTP 提交后的同步快路只领取本次事务返回的任务 ID，不消费全局积压；领取、执行或结果查询异常时仍返回已经提交的 Tracking 响应，由定时 Worker 继续处理。任务自动尝试耗尽后进入 `FAILED`，操作者重放同一运单接收/京东回填动作会把该同键终态任务安全复活为 `PENDING`；进行中和已成功任务不会被重置。
