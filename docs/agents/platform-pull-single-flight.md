# 平台拉单并发单飞（#115，按用户口径修订）

## 结论

平台拉单原本没有“每日次数”或“最小间隔”业务限制，因此本实现不新增频率限制、每日配额、`last_pull_at` 配额扣减，也不在发货台展示“今日剩余次数”。#115 只修复同一渠道被并发点击时重复触发真实外部拉取的问题。

## 并发语义

每个渠道在真实拉取开始前，通过独立 PostgreSQL session 获取由渠道名派生的 session advisory lock：

- 同一渠道同一时刻只有一个请求进入真实 Connector；
- 不同渠道互不阻塞；
- 锁覆盖外部拉取、结果持久化、状态与审计收口的完整窗口；
- 第二个并发请求不等待、不触网，渠道结果为 `PLATFORM_PULL_IN_PROGRESS`；
- 拉取成功或失败都会在收口后释放锁；失败不“占用次数”，之后可立即重新发起；
- 进程或数据库连接异常断开时，PostgreSQL 自动释放 session lock，不留下永久占用。

锁使用专用连接，不能放回连接池后再解锁；释放时校验 `pg_advisory_unlock` 结果。前端另有同页面请求中的本地按钮防重复，但数据库单飞才是跨浏览器、跨实例的权威并发边界。

## 验证

`PlatformOrderRefreshConcurrencyIntegrationTest` 使用真实 PostgreSQL 与两个并发请求，证明恰一个请求触达外部拉取 seam、另一个得到 `PLATFORM_PULL_IN_PROGRESS`，并验证失败/连接释放后的后续请求可继续执行。该测试证明的是并发单飞，不代表任何频率或配额制度。
